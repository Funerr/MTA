# MTA 后续路线图

本文件只记录未来工作，不维护已完成 Change 清单或测试数量。当前能力见 [README](../README.md)，边界见 [ARCHITECTURE](../ARCHITECTURE.md)，阶段证据见 [验收索引](../docs/acceptance-index.md)。以下是工作方向，不代表已批准实施的新能力。

## 第一优先：验证现有 Experience 闭环

在冻结范围内验证学习 → candidate → 画面匹配 → 重放 → 失配回退 → 再学习。重点补充 Android / HarmonyOS 真实设备和真实模型证据，区分受控测试结论与现场效果。

| 待验证项 | 所需证据 |
| --- | --- |
| 合格纯动作首次学习与重复复用 | 原生调用次数、候选生成、命中后的模型请求数、报告关联 |
| 页面变化与目标位移 | 当前画面匹配结果、实际派发坐标、拒绝误匹配的记录 |
| 中途失败、取消、超时、未知副作用 | 停止/回退决策、设备 I/O 状态、无盲目重复执行 |
| Store / Promotion 失败 | 原生结果保留、学习失败可见、无重复动作 |
| 多设备交错与并行 | 精确绑定、逐设备报告、在途操作和销毁时序 |

现场验证按单台 → 交错 → 并行推进。记录日期、设备与模型配置、使用的示例/验收工作流及局限；只有实际执行过的项才能形成验收结论。

## 后续治理

1. 在维护现有功能时逐步收口 Midscene dump/report/executionId 访问，复用现有 Adapter 职责并验证锁定依赖契约。
2. 后续新增示例放 `examples/`；是否迁移既有示例及调整发现配置，单独评估路径和运行入口兼容性。

## 研究方向：高层 Case Authoring

用例转换的草稿与交付约定已接入本地 GUI（[用例编写工作台](../README.md#用例编写工作台)，2026-09 验收）；编写层 SDK 与真实设备上的模型/核查评估仍在后续范围。状态变化和持续行为断言需要先验证证据传递与比较契约，再决定是否扩展通用观测能力；不通过增加业务 Node 构建业务 DSL。当前入口见 [README](../README.md)，此处不承诺交付时间。

## 暂停扩展

Memory、Skill、通用 Recovery 等 Experience 大能力暂停；生产断言增强也不作为本阶段实施项。先评估闭环证据，再由用户决定是否解除冻结、启动后续设计。具体工程约束见 [AGENTS.md](../AGENTS.md)。
