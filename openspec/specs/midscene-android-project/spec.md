# midscene-android-project Specification

## Purpose

为框架使用方提供可安装、可配置的 Android 会话和原生测试能力接入，明确环境选择、资源生命周期、能力发现及报告接口，使后续经验模块具有可验证的基础而不依赖框架交付具体业务用例。

## Requirements

### Requirement: 工程与能力发现

项目 SHALL 提供可复现依赖安装、框架测试、类型检查和 Node 参考生成入口，覆盖 android 与 harmony 两个执行项目。安装、配置加载及这些检查 MUST 不要求已连接设备或实际模型密钥；业务执行入口使用原生 CLI 并接受使用方提供的内容，android 项目 SHALL 仅发现项目声明为 android 的项目结构内用例（`cases/<项目>/**`），文件名后缀 MUST NOT 参与发现或平台判定。

#### Scenario: 无外部环境的工程检查

- **WHEN** 开发者在支持的主机上安装锁定依赖、执行类型检查、框架测试和 Node 参考生成
- **THEN** 检查可在没有设备/模型密钥的条件下完成，参考中包含两平台原生 aiAct/aiAssert、各自平台 shell 节点（`runAdbShell`/`runHdcShell`）与通用生命周期 Nodes

#### Scenario: 业务内容由使用方提供

- **WHEN** 使用方将自己的合法 YAML 放入项目声明为 android 的项目结构（如 `cases/EV760/<大模块>/<特性>/`）
- **THEN** android 项目提供原生注册和运行入口，不要求先具备框架内置业务示例、专用用例格式或文件名平台后缀

### Requirement: 确定性的设备选择

项目 SHALL 支持 ANDROID_DEVICE_ID；未指定时只在恰有一台授权在线设备时自动选择。目标无效或选择歧义 MUST 在 UI 操作前失败，不能静默切换设备。

#### Scenario: 目标明确

- **WHEN** 指定设备可用，或未指定且只有一台可用设备
- **THEN** 会话绑定该设备并输出所选标识

#### Scenario: 选择或环境失败

- **WHEN** 目标不存在/离线/未授权、未指定且多台设备可用，或所需运行环境不可用
- **THEN** 返回能够定位原因的错误，不派发 UI 操作或报告成功

### Requirement: 会话资源生命周期

框架 SHALL 在执行期创建会话并通过原生 context 供 Nodes 使用；正常结束、执行失败及部分初始化失败后 MUST 释放已取得资源，保留原始错误和清理错误。

#### Scenario: 正常释放

- **WHEN** 受控边界集成测试完成一次会话并再次创建
- **THEN** 前次资源只释放一次，新会话不复用已销毁对象

#### Scenario: 初始化失败

- **WHEN** 已取得部分资源后发生初始化错误
- **THEN** 已取得资源被清理，未创建对象不被销毁，错误保持可见

### Requirement: 原生报告与契约保留

框架 SHALL 保留原生 Node 输入、返回、失败及报告关联，不重建 Runner 或报告渲染；运行产物与框架实现、经验资产分离。

#### Scenario: 失败结果接入

- **WHEN** 原生边界集成夹具注入节点或清理失败
- **THEN** 原生结果可追踪相关错误和步骤关联，框架不将失败改为成功

#### Scenario: 产物隔离

- **WHEN** 框架集成测试生成原生报告
- **THEN** 报告写入配置的运行目录，不被当作 experiences/ 中的经验；实际环境配置与运行产物不默认纳入版本管理

### Requirement: 框架验收范围

交付 SHALL 包含工程检查、项目新增逻辑测试及实际锁定依赖的原生边界集成验证，MUST 区分替身与真实设备证据。具体业务 YAML、业务流程执行与业务状态判断不作为本能力交付要求。

#### Scenario: 无业务用例完成框架验收

- **WHEN** 安装、类型、注册、设备选择、资源清理与原生边界集成检查通过
- **THEN** 可判定本框架阶段完成，不要求提交业务用例或业务执行报告，也不宣称已经验证真实设备业务效果
