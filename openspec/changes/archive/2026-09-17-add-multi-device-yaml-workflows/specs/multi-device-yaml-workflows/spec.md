## Purpose

让使用方沿用 Midscene Test 的 YAML 用例，在一个执行项目中明确绑定多台 Android 或 HarmonyOS 设备，并以可追踪的步骤交错或同时操作这些设备，而无需在业务用例中管理 Agent 生命周期。

## ADDED Requirements

### Requirement: 明确的多设备绑定

多设备协作项目 SHALL 接受至少两条设备声明；每条声明 MUST 具有在项目内唯一的别名、平台和显式设备标识。系统 SHALL 在任何用例 UI 操作之前确认所有声明的设备可用，同一物理设备 MUST 不得被两个别名重复绑定，且 MUST 不静默改选设备。

#### Scenario: 成功绑定不同平台的设备

- **WHEN** 配置了两个或更多不同设备，其中设备可来自 Android 与 HarmonyOS 的任意组合
- **THEN** 用例可通过各自别名访问已绑定的设备，并能看到别名与实际设备标识的对应关系

#### Scenario: 缺失、重复或不可用的设备

- **WHEN** 别名或设备标识缺失、同一设备重复绑定、目标未连接或连接失败
- **THEN** 协作项目在首个用例 UI 步骤前失败，报告可定位的别名与设备标识，不操作其他已绑定设备

### Requirement: YAML 顺序步骤的目标设备明确

协作项目 SHALL 为每个设备别名提供目标明确的 YAML Node 调用方式，使一个用例可按声明顺序交错调用不同设备的原生操作与断言。未声明的设备别名或该平台不支持的操作 MUST 在执行设备操作前失败。单设备项目现有 YAML Node 名称、输入和用例发现范围 MUST 保持兼容。

#### Scenario: 交错执行

- **WHEN** 一个 YAML 用例依次声明设备甲动作、设备乙动作、设备甲断言
- **THEN** 三个步骤按声明顺序分别交给目标设备执行，并在结果中标识各步骤的设备别名

#### Scenario: 错误的目标或操作

- **WHEN** 用例调用未声明别名或目标平台没有的 Node
- **THEN** 用例在该操作派发前失败，不把操作路由到其他设备

### Requirement: YAML 并行步骤

协作项目 SHALL 提供一个自定义并行 Node，接受至少两个分别指定已绑定设备的子操作，且同一并行步骤内每台设备最多出现一次。子操作 SHALL 同时发起；并行步骤 SHALL 在所有子操作完成后汇合，并在任一子操作失败时失败。超时或取消 MUST 传递给未完成的子操作，后续操作 MUST 不得与同一设备上尚未结束的子操作重叠。

#### Scenario: 不同设备同时执行

- **WHEN** 并行步骤包含设备甲和设备乙上的有效操作
- **THEN** 两个操作在同一次并行步骤中均被发起，步骤在二者结束后给出各自结果

#### Scenario: 子操作失败或超时

- **WHEN** 任一子操作失败，或并行步骤超时
- **THEN** 用例不会报告成功，结果包含失败的设备别名与子操作；所有尚未结束的操作收到取消通知，后续步骤不会与其重叠

### Requirement: 资源与报告可追踪

项目 SHALL 为每台设备分别管理 Agent 生命周期。正常结束、用例失败和部分初始化失败时，已取得的资源 MUST 被释放，释放失败 MUST 可见且不得遮蔽原始执行错误。顺序和并行步骤的结果 MUST 可定位到设备别名、原生操作及相关执行轨迹；并行子操作的成功 MUST 不掩盖其他子操作的失败。

#### Scenario: 部分初始化失败

- **WHEN** 前一台设备已建立会话而后一台设备连接失败
- **THEN** 前一台会话被释放一次，后一台已取得的部分资源被清理，原始连接错误保持可见

#### Scenario: 并行结果关联

- **WHEN** 两台设备的并行操作分别成功和失败
- **THEN** 报告中能区分两台设备的结果与相关轨迹，整个并行步骤和用例均标记失败
