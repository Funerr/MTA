## Context

输入由前序 Promotion 生成的真实视觉资产提供。匹配不是新的通用 Locator：只对历史页面与目标提出接受或拒绝，所有设备操作仍交给 Midscene。

实施前置：[add-experience-model](../add-experience-model/proposal.md)、[add-experience-promotion](../add-experience-promotion/proposal.md)。本次为提前规划，前置完成后先核对实际契约。

## Goals / Non-Goals

**Goals:** 用确定性的本地计算获得当前目标框，并通过可复现正反例证明首期接受范围。

**Non-Goals:** 不引入新 VLM、网络 OCR、任意缩放/旋转匹配、自适应线上降阈值和全局语义定位。

## Decisions

### 1. 本地流水线

matcher/screen.ts 做环境与页面检查，target.ts 搜索历史模板，text.ts 提供可选本地 OCR 证据，confidence.ts 合成判定。v1 默认使用本地图像解码、pHash 粗筛、模板归一化相似度及上下文/局部 SSIM 检查；底层包在实施前用小样本和当前 Node 平台安装验证后锁定。OCR 首版默认关闭，只有固定模型、语言包和独立测试均满足时作为附加条件开启，不成为缺省可用性的前提。

### 2. 位置与状态

历史 bbox 限定有限搜索范围，但不直接作为结果。首期声明支持范围为相同尺寸/方向图像中，目标水平或垂直移动不超过截图对应尺寸的 3%，目标尺寸不变且不被截断；输出实际找到的框。页面动态状态栏可以用固定掩码处理，但不得掩盖目标或其状态/上下文。开关前置状态的局部证据必须匹配，pHash 的全屏高相似度不能覆盖开关状态差异。

### 3. 分项硬条件

接受需要 environment、screen、target、context 逐项通过；有文本要求时 text 也通过。置信度给出各项值、阈值和 top1/top2 差距；不把分数解释为准确概率。两个可接受候选过近、多个同等位置或状态不同都拒绝。算法阈值在校准集一次确定、写入版本配置并冻结；验证失败则不能发布该版本，禁止对验证集逐例特调。

### 4. 数据与验收

从 Promotion 生成的资产或具有明确来源的通用控件截图构造夹具，覆盖原图、±1%/±3% 位移、不同页同图标、移除、遮挡、开关已开启和入口结构变化。校准和验证按原始捕获分组，所有变体随同原图进入同一组，避免泄漏。验证清单记录期望 accept/reject 与可接受 bbox；正例中心必须落入目标，负例无错误接受。合成位移是框架算法的有效验证输入，记录生成方法和范围；不要求构造真实设备业务页面的位移，也不据此宣称真实设备覆盖率。

### 5. 接口和有界开销

matchScreen/matchTarget 返回 match/no-match 及诊断，不获取设备截图、不调 AI、不更新 Store。输入尺寸、搜索区和候选数有上界，记录本地耗时；图片/参数错误给结构化原因。耗时作为测量结果，不在未测量前承诺绝对性能倍数。

## Risks / Trade-offs

- [模板对主题/系统差异敏感] → 依赖严格 Variant 环境隔离，变化走后续 AI 回退。
- [阈值太高导致频繁 MISS] → 首期接受低命中率，先保证冻结负例不误点。
- [局部误匹配] → 页面、目标、上下文和前置状态共同校验，拒绝歧义。

## Migration Plan

先独立运行夹具评估，再交 Replay 使用；变更 matcher 配置版本时保留校准记录并重新验收，不能自动放宽已有经验的限制。
