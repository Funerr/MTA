## Context

动机见 [proposal.md](proposal.md)。本变更跨越编写模型、Web 服务、文件转换和设备会话，需要独立设计。现有 [架构](../../../ARCHITECTURE.md) 已区分 Case Authoring 与 Runtime；[转换交付约定](../../../.agents/skills/case-to-yaml/references/conversion-contract.md) 提供草稿、覆盖关系和逐用例状态，但尚无 HTTP 服务。Android/HarmonyOS 会话工厂已经存在，不能据此推定编写服务的取消和核查契约已验证。

## Goals / Non-Goals

**Goals:** 将业务要求、平台工作流和现场证据关联；以同一版本支持步骤视图和 YAML 编辑；复用现有执行与设备能力，提供本地单用户闭环。

**Non-Goals:** 不将编写草稿变成业务 DSL 或新 Node；不承诺任意 YAML 都能转换成可编辑卡片；不建设完整测试执行管理界面、实时视频投屏或设备集群。

## Decisions

### 1. 本地 Web 服务承载编写能力

采用浏览器前端、Node/TypeScript 本地服务和文件存储。服务默认监听回环地址，保存模型配置和凭据，前端不接触密钥；校验请求来源，限制文件访问在编写工作区内。相比纯浏览器方案，本地服务能接入 ADB/HDC 和现有 MTA；相比云服务，无需新增设备代理。前端框架和编辑器库作为实现选型，不改变规格。

服务提供项目配置、草稿修订、模型生成、静态校验、核查启动/停止/接管、证据读取、确认导出等接口；耗时操作返回任务标识，并以事件流传递进度。模型失败、取消或断连保留上一次完整草稿，不发布半成品为已确认版本。

### 2. 一个编写文档保存三类内容

编写文档保留原始来源、结构化业务用例以及每个平台的工作流版本。沿用现有草稿和转换记录字段，外层增加名称、等级、版本和核查关联，不向执行 YAML 注入这些元数据，也不默默改变既有 format_version 的含义。

用例、动作、预期使用稳定 ID；源编号可重复或缺失。步骤允许零个或多个预期，整条用例须保留全部业务预期。平台变体保存项目、应用上下文、执行内容、覆盖映射和证据。业务要求变化会标记所有受影响平台待更新；仅平台操作变化不修改另一个平台的内容。

草稿保存允许字段不完整；进入生成前突出名称、步骤、预期、等级及关键上下文的缺失，允许显式声明无前置条件，不猜包名或设备 ID。模型可帮助整理，但不静默填补业务要求。首版等级为 level1/level2/level3，沿用现有发现配置，不强加额外优先级语义。

### 3. 两阶段界面与可追溯转换

录入页提供表单、整段粘贴和 Excel/Markdown/文本导入，解析后统一展示表单供核对。保留来源范围、原文、跨行关系及未转换清单；表格空白预期不向下填充。编写页默认显示步骤卡片，旁边显示设备截图和核查进度；原文和 YAML 可切换查看。

转换服务加载当前项目的 skill 规则、YAML 指南及目标 Node 契约，使用可配置模型生成结构化结果，并由服务校验。编写模型与设备视觉模型可以分别配置；提供者差异封装在模型调用边界，不要求用户使用特定品牌。导入文件内容只作为数据，不作为工具调用指令。UI 展示覆盖缺口、改写理由和静态检查范围。

### 4. 用例视图是执行内容的确定性投影

平台工作流使用保留注释与未知节点的 YAML 文档表示，步骤视图由确定性映射生成，不能由另一轮模型摘要代替。卡片支持本产品生成的顺序动作、断言及必要准备步骤；一个业务步骤可以映射多个 YAML 节点。并行等超出卡片能力的有效结构显示保留块，可在 YAML 中修改。

卡片编辑更新对应文档节点并校验；原始 YAML 编辑先保留为候选缓冲区，语法解析成功才替换当前文档。无效文本不会让卡片继续冒充当前编辑结果，界面明确显示未同步并阻止确认。支持结构须通过卡片→YAML→卡片往返测试；有效但未支持的结构保留原文，不进行有损重建。

模型生成结果携带基础修订号与局部修改范围。若用户已继续编辑，生成结果作为待合并差异展示，禁止覆盖新内容；人工改写及其来源单独记录。相比两个独立可写模型，这种方案降低视图漂移风险，但限制了首版可视化覆盖范围。

### 5. 设备核查统一提交现有 MTA 执行链路

工作台负责录入、编写、设备选择、提交请求与结果展示。所有设备核查统一走“工作台 → MTA 项目配置与 Runtime → Midscene Runner → Node / Agent / Planner”链路，复用既有项目的 Node 注册、setup/teardown、执行上下文、变量、取消和报告契约。不得在工作台抽取 YAML 节点后循环调用 aiAct/aiAssert，也不得绕过 MTA 单独组织 Agent 执行。

用户绑定平台和设备后启动核查，工作台将明确目标、必要前置路径、目标动作和观测点整理成现有框架支持的工作流，固定本次内容修订与范围后提交执行。局部核查与完整用例使用同一执行机制，区别仅在已明确的工作流范围。片段必须保留原节点、结构化参数和必要生命周期；aiTap 不得改为 aiAct，launch、device.prepare 等必要节点不得被静默省略。同一次核查中共享的前置路径只按工作流执行一次，不为每个观测点从头重放。无法确定依赖闭包或安全核查范围时返回缺口，不静默扩大到完整用例或猜测动作。一次启动覆盖展示的范围，不逐点击要求确认。业务准备条件未知时返回问题，不自行引入恢复流程。

精确设备绑定传入既有 MTA 会话边界，由框架管理执行会话的获取与释放；工作台不得为同一执行另建旁路 Agent 会话。观测和报告复用现有 Adapter 职责，以原生执行结果关联目标与证据，事件通知不能冒充动作已完成。没有明确预期的步骤仅记录观察，不自动生成模糊 aiAssert 或通过状态。必要接口封装必须在相应边界完成并验证锁定依赖；不将 Experience 学习/重放默认接入编写过程。

同一设备同一时刻只允许一个工作台控制任务。工作台向框架执行适配入口传递取消请求，以底层执行与会话释放状态展示停止进度，不实现节点级调度或重试循环。停止后禁止派发新动作，等待在途调用按底层契约结束；只有控制权已释放才显示可人工接管。无法确认停止时显示停止中或状态未知，不能宣称设备已空闲。人工操作结束后重新获取画面再恢复。设备断连不自动切换另一台设备；服务重启将未完成任务标为中断，不自动重放。外部命令行占用不在工作台锁的保障范围，连接说明需明确独占使用要求。

### 6. 证据、校验与确认相互独立

每条证据关联用例/步骤 ID、平台、精确设备绑定、采集时间、工作流修订、核查目标、前置路径和截图/原生报告引用。证据说明事实及其局限，不能用“按钮存在”证明功能生效。业务要求、动作、前置路径、平台或设备上下文变化时，相关证据标为待复核；下游步骤证据随前置动作变化失效，原记录仍可查。

静态校验分别报告 YAML 解析、目标 Node/输入契约、预期覆盖和证据路径可用性。复用纯收集/校验入口，不能启动 setup 来做静态检查；若现有依赖没有合适公开入口，封装纯校验适配并补充契约测试，完成前标记 unvalidated。状态变化等断言缺少已验证的数据传递能力时保留草稿，不伪造可执行结果。

继续沿用 ready/needs_clarification/unsupported/unvalidated 表示转换就绪度；另外保存核查状态和人工确认状态。未实际核查不是自动失败；与生成正确性相关的关键疑点未解决则阻止就绪。完整执行默认未运行，关键点核查不修改它。

确认绑定具体内容修订与摘要，生成不可变快照。默认在 `artifacts/case-to-yaml/<会话>/` 下保存原文、草稿、转换记录、证据及按平台区分的输出；应用项目后缀按现有配置核定。只将 ready 且已确认的用例纳入执行导出，排除项明确列出；未就绪内容允许保存为标明状态的草稿。无就绪内容时不生成空的执行文件。确认后修改创建新草稿，导出前检查当前修订，防止导出旧确认冒充最新内容。完整执行留给已有 MTA 入口。

## Risks / Trade-offs

- [任意 YAML 往返编辑复杂] → 明确卡片支持子集，其余保留为原始块；不承诺无损业务语义反推。
- [设备核查耗时、改变现场状态] → 限定核查目标、展示动作和停止状态，记录前置环境；不静默重试未知副作用操作。
- [模型输出不稳定] → 结构校验、覆盖检查、版本冲突保护；失败保存草稿，禁止自动放宽验收要求。
- [双平台接入成本与可用设备差异] → 分别进行真实设备验证，缺平台证据则记录未验收，替身测试不能冒充现场通过。
- [本地文件和截图包含测试数据] → 模型密钥仅服务端保管，日志脱敏，文件读写限制于工作区；数据按配置发送到用户选择的模型服务。

## Migration Plan

先替换现有 `src/workbench/core/verify/runner.ts` 的自建步骤派发及 `goals.ts` 的字符串动作提取，调整 `server/verify-service.ts` 通过框架执行适配入口提交核查；原有直接 Agent 替身测试不能作为整条框架链路的验收。

以独立启动入口增量加入工作台，既有 CLI、用例发现规则和默认设备 alias 保持兼容。先验证同步与会话契约，再接通模型、双平台核查及完整人工确认流程。只在完成后更新 README 当前能力和带日期的验收记录。回滚时停用新增入口即可；草稿独立保存，不迁移或覆盖已有 cases。新增演示放 examples，测试夹具放 tests/fixtures。

## Open Questions

- 实施环境采用的模型提供者、模型名称与端点由本地配置确定，具体凭据不写入仓库。
- 前端框架、YAML 编辑器及 Excel 解析依赖在实现时按维护性与打包体积选择，行为必须满足同一规格。
